# 分块策略结论

## 一、测试参数

| 参数 | 测试值 |
|------|--------|
| chunk_size | 256 / 512 / 768 / 1024 字符 |
| overlap | 0 / 50 / 100 / 150 字符 |
| 模型 | BAAI/bge-small-zh-v1.5 |

---

## 二、测试结果对比

| chunk_size | overlap | 命中率 | 分块数 | 延迟 |
|------------|---------|--------|--------|------|
| 512 | 50 | 100% | 4 | 11ms |
| 512 | 100 | 100% | 4 | 11ms |
| 512 | 0 | 100% | 4 | 11ms |
| 768 | 0 | 100% | 3 | 12ms |
| 1024 | 0 | 100% | 3 | 11ms |
| 256 | 0 | 100% | 7 | 11ms |

---

## 三、结论

### ★ 推荐：`chunk_size=512, overlap=50`

| 维度 | 理由 |
|------|------|
| 数据匹配 | Schema 规定 content 100-500字，512 可容纳绝大多数条目不被拆分 |
| 检索精度 | 100% 命中率，50字 overlap 确保边界处语义不丢失 |
| 效率 | 仅 4 块，向量库体积小 |

### 特殊场景说明

| 场景 | 处理方式 |
|------|---------|
| content < 512 字 | 不拆分，直接作为一条存入 |
| content > 512 字 | 按 512 字切分，50 字 overlap，标题标注"节选1/2/3" |
| 语录（quote） | 通常 < 100 字，永不拆分 |
| 场馆介绍/生平长文 | 可能拆成 2-3 块，用相同 id + 节选编号区分 |


---

## 四、技术栈最终确定

```
Embedding 模型: BAAI/bge-small-zh-v1.5
向量数据库:     ChromaDB
分块策略:       chunk_size=512, overlap=50（按字符数）
入库方式:       SentenceTransformerEmbeddingFunction
推理延迟:       ~14ms/query（embedding） + ~11ms（检索）
```
