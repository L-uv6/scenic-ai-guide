# 知识库数据 Schema 规范

---

## 一、五大知识域

| type 标签 | 知识域 | 说明 | 数据量目标 |
|-----------|--------|------|-----------|
| `venue` | 场馆知识 | 广州鲁迅纪念馆：建筑、展厅、展品、参观信息 | 30+ 条 |
| `work` | 作品知识 | 鲁迅代表作原文段落（小说、散文、杂文、诗歌） | 100+ 条 |
| `bio` | 生平知识 | 鲁迅生平时间线：关键事件、人际关系、地域轨迹 | 50+ 条 |
| `quote` | 经典语录 | 名言、金句、书信摘录 | 80+ 条 |
| `persona` | 人物性格 | 语言风格、习惯用语、价值观念、性格特征 | 20+ 条 |

---

## 二、JSON Schema 定义

### 2.1 单条知识条目

```json
{
  "id": "work_001",
  "type": "work",
  "title": "《狂人日记》节选",
  "content": "我翻开历史一查，这历史没有年代，歪歪斜斜的每页上都写着'仁义道德'几个字。我横竖睡不着，仔细看了半夜，才从字缝里看出字来，满本都写着两个字是'吃人'！",
  "source": "《狂人日记》，1918年5月发表于《新青年》第四卷第五号",
  "year": 1918,
  "tags": ["小说", "呐喊", "批判", "礼教", "白话文"],
  "character_voice": true,
  "venue_relevant": false
}
```

### 2.2 字段规范

| # | 字段 | 类型 | 必填 | 说明 |
|---|------|------|------|------|
| 1 | `id` | string | ✅ | 唯一标识，格式：`{type}_{序号}`，如 `venue_001`、`work_012` |
| 2 | `type` | enum | ✅ | 取值为 `venue` / `work` / `bio` / `quote` / `persona` |
| 3 | `title` | string | ✅ | 知识条目标题，简洁明了，10-30字为宜 |
| 4 | `content` | string | ✅ | 知识正文，用于向量化和检索的核心字段 |
| 5 | `source` | string | ✅ | 数据来源，需具体到篇目/URL/书名+出版信息 |
| 6 | `year` | int | 推荐 | 年份，鲁迅生平事件用实际年份，作品用发表年份。公元前用负数 |
| 7 | `tags` | list | 推荐 | 关键词标签，每条3-8个，辅助关键词匹配和过滤 |
| 8 | `character_voice` | bool | 推荐 | 是否适合用作"鲁迅口吻"的素材，默认 false |
| 9 | `venue_relevant` | bool | 推荐 | 是否与广州鲁迅纪念馆直接相关，默认 false |

### 2.3 字段详细说明

#### `id` — 唯一标识

- **格式**：`{type}_{序号}`，序号从 001 开始，三位数字补零
- **规则**：同 type 下 id 唯一，不能重复
- **示例**：`venue_001`、`work_045`、`bio_012`、`quote_078`、`persona_005`

#### `type` — 知识域类型

| 取值 | 含义 | 使用场景 |
|------|------|---------|
| `venue` | 场馆知识 | 纪念馆建筑、展厅、展品、参观信息 |
| `work` | 作品知识 | 鲁迅创作的小说、散文、杂文、诗歌等原文段落 |
| `bio` | 生平知识 | 鲁迅生平事件、人际关系、地域轨迹 |
| `quote` | 经典语录 | 广为流传的名言警句、书信摘录 |
| `persona` | 人物性格 | 语言风格描述、性格特征、价值观念 |

#### `title` — 标题

- 原则上不超过 30 字
- 作品类：`《篇名》节选` 或 `《篇名》+ 段落主题`
- 生平类：`时间 + 事件概述`，如 `1898年赴南京求学`
- 语录类：用原句（前15字截断+省略号），如 `"横眉冷对千夫指，俯首甘为……"`
- 场馆类：`展品/展厅名称 + 简介`
- 性格类：`特征概括`，如 `鲁迅的冷峻文风`

#### `content` — 知识正文

- **核心字段**，向量化、检索、LLM拼接均以此字段为主
- 长度建议：**100-500字**，过长不利于检索精度，过短信息量不足
- 作品类：选取有鲜明观点/情感/文风的段落原文
- 生平类：客观陈述，包含时间+地点+人物+事件
- 语录类：完整原句，标注出处
- 场馆类：事实准确，包含位置/功能/历史
- 性格类：描述性文本，引用后人评价或作品分析时需标注来源

#### `source` — 数据来源

- **必须可追溯**，不能写"网络来源"这种模糊表述
- 格式参考：
  - 作品：`《篇名》，XX年发表于《刊物名》`
  - 书籍：`《书名》，作者，出版社，出版年份`
  - 网页：`网站名 + URL（最后访问日期）`
  - 学术论文：`《论文标题》，作者，期刊，年份`

#### `year` — 年份

- 作品类填发表年份，生平类填事件年份
- 年份不详可填 0 或省略
- 公元前用负数：如 `-551` 表示公元前551年
- 用于阶段3的**时间穿越检测**（鲁迅只知道1936年及以前的事）

#### `tags` — 关键词标签

- 每条 3-8 个标签，用词准确、统一
- 建议标签体系（各 type 通用 + 专属）：

| type | 推荐标签 |
|------|---------|
| venue | 建筑、展厅、展品、参观、历史沿革、广州、钟楼 |
| work | 小说、散文、杂文、诗歌、呐喊、彷徨、朝花夕拾、野草、批判、讽刺 |
| bio | 出生、求学、留学、任教、避难、上海、北京、广州、日本、文学革命 |
| quote | 名言、金句、批判、激励、人生、青年、文学、社会 |
| persona | 文风、语言习惯、价值观、性格、待人接物 |

#### `character_voice` — 鲁迅口吻标记

- `true`：这段文字体现了鲁迅独特的语言风格，适合用作数字人模式的检索素材
- `false`（默认）：普通知识条目，不适合扮演鲁迅时使用
- **典型 true 场景**：鲁迅原文段落、犀利观点、典型句式
- **典型 false 场景**：场馆客观介绍、生平客观陈述、后人评论

#### `venue_relevant` — 场馆相关标记

- `true`：与广州鲁迅纪念馆直接相关（建筑、展厅、广州时期生平、白云楼、钟楼等）
- `false`（默认）：与场馆无直接关联
- **典型 true 场景**：纪念馆展厅介绍、广州时期8个月生平、广州时期作品
- **作用**：讲解模式下可优先检索 `venue_relevant=true` 的条目

## 四、数据文件组织

### 4.1 目录结构

```
data/
├── raw/                          # 原始采集数据（采集阶段暂存）
│   ├── venue_raw.json
│   ├── work_raw.json
│   ├── bio_raw.json
│   ├── quote_raw.json
│   └── persona_raw.json
└── processed/                    # 审核通过、格式化后的数据
    ├── venue.json                # 所有 venue 条目 → Vector DB
    ├── work.json                 # 所有 work 条目 → Vector DB
    ├── bio.json                  # 所有 bio 条目 → Vector DB
    ├── quote.json                # 所有 quote 条目 → Vector DB
    └── persona.json              # 所有 persona 条目 → Vector DB
```

### 4.2 文件格式

每个 `processed/*.json` 文件是一个 JSON 数组，包含该 type 下的所有知识条目：

```json
[
  { "id": "venue_001", "type": "venue", ... },
  { "id": "venue_002", "type": "venue", ... }
]
```

### 4.3 ID 序号分配

| type | ID 段 | 分配人 |
|------|-------|--------|
| venue | venue_001 ~ venue_030+ |  |
| work | work_001 ~ work_100+ |  |
| bio | bio_001 ~ bio_050+ |  |
| quote | quote_001 ~ quote_080+ |  |
| persona | persona_001 ~ persona_020+ |  |

## 五、数据质量标准

### 5.1 硬性要求

| 检查项 | 标准 |
|--------|------|
| id 唯一性 | 不得与已有条目重复 |
| type 正确 | 必须在 5 种 type 枚举值内 |
| content 非空 | 至少 50 字（场馆类可放宽到30字） |
| source 可追溯 | 不能是"网络来源""百度"等模糊表述 |
| 必填字段完整 | `id` `type` `title` `content` `source` 缺一不可 |

### 5.2 软性要求

| 检查项 | 标准 |
|--------|------|
| tags 数量 | 建议 3-8 个，少于3个扣分 |
| year 完整性 | 作品/生平类应填年份，缺少扣分 |
| character_voice 标注 | 作品/语录类应标注，缺少扣分 |
| content 长度 | 建议 100-500 字，过短/过长扣分 |
| 错别字/标点 | 全文审阅，发现错误扣分 |
