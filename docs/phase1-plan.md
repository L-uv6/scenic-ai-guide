## 一、总体设计

### 1.1 五大知识域

| 域 | type标签 | 内容说明 | 数据量目标 | 优先级 |
|----|---------|---------|-----------|--------|
| 🏛️ 场馆 | `venue` | 纪念馆建筑、展厅布局、展品信息、参观须知 | 30+条 | 🔴 P0 |
| 📖 作品 | `work` | 鲁迅代表作原文（小说、散文、杂文、诗歌） | 100+条 | 🔴 P0 |
| 👤 生平 | `bio` | 时间线、关键事件、人际关系、地域轨迹 | 50+条 | 🔴 P0 |
| 💬 语录 | `quote` | 名言、金句、书信摘录 | 80+条 | 🟡 P1 |
| 🎭 性格 | `persona` | 语言风格描述、习惯用语、价值观念 | 20+条 | 🟡 P1 |

> 📊 **数据量底线**：阶段1结束前至少入库 **300条** 知识条目，其中 venue+work+bio 至少200条。

### 1.2 知识库 Schema

每条知识条目统一格式：

```json
{
  "id": "work_001",
  "type": "work",
  "title": "《狂人日记》",
  "content": "我翻开历史一查，这历史没有年代，歪歪斜斜的每页上都写着'仁义道德'几个字。我横竖睡不着，仔细看了半夜，才从字缝里看出字来，满本都写着两个字是'吃人'！",
  "source": "《狂人日记》，1918年发表于《新青年》",
  "year": 1918,
  "tags": ["小说", "呐喊", "批判", "礼教"],
  "character_voice": true,
  "venue_relevant": false
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | 唯一标识，格式：`{type}_{序号}` |
| `type` | enum | ✅ | `venue` / `work` / `bio` / `quote` / `persona` |
| `title` | string | ✅ | 知识条目标题 |
| `content` | string | ✅ | 知识正文（用于向量化和检索） |
| `source` | string | ✅ | 数据来源标注 |
| `year` | int | 推荐 | 年份（鲁迅生平/作品发表时间），用于时间约束 |
| `tags` | list | 推荐 | 关键词标签，辅助检索 |
| `character_voice` | bool | 推荐 | 是否适合用作"鲁迅口吻"的素材 |
| `venue_relevant` | bool | 推荐 | 是否与广州/纪念馆直接相关 |

### 1.3 数据流程

```
数据采集 ──→ 数据清洗/格式化 ──→ 审核 ──→ 入库（JSON文件+Chroma向量库）
                                                    │
                                           ┌───────┴──────┐
                                           │              │
                                      JSON存储       向量存储
                                   (原始数据备份)   (用于语义检索)
```

## 四、验收标准

阶段1通过验收，以下必须全部满足：

- [ ] 数据总量 ≥ **300条**（venue≥30, work≥100, bio≥50, quote≥80, persona≥20）
- [ ] 所有数据按schema格式化，字段完整（`id`, `type`, `content`, `source` 必填项缺失率=0）
- [ ] Chroma向量库可查询，top-5检索结果至少3条相关
- [ ] 大一C的50个问题中，至少 **40个能在知识库中检索到相关内容**
- [ ] 用大一B的Prompt v1 + 检索结果调用LLM，至少能对场馆类和人物类问题各回答3个，且回答不空洞
- [ ] 所有代码提交到Git仓库
